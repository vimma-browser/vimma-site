vimma-ctl controls a running Vimma from the command line: send it keys, read its state, open a URL. Use it from scripts or window-manager bindings. It is off until you turn it on.

Before you turn it on

The control socket (vimma.control.enabled) gives full control of the browser to any program running as your user: such a program can type into your logged-in sites, change any setting and open local files. Leave it off unless you script Vimma. AI agents do not need it: :mcp on lets them reach only the agent workspace, and Vimma asks you before each request (below).

Set it up

  1. In about:config, set vimma.control.enabled to true. It starts at once.
  2. Use the vimma-ctl that came with Vimma; it is updated with it:
    • .deb, .rpm, Arch Linux and Homebrew: already on your PATH.
    • Tarball: vimma/vimma-ctl, next to vimma/vimma; link it onto your PATH.
    • AppImage: a link named vimma-ctl to the AppImage runs it, such as ln -s ~/Apps/vimma-X.Y.Z-x86_64.AppImage ~/.local/bin/vimma-ctl.
    • .dmg: /Applications/Vimma.app/Contents/MacOS/vimma-ctl.

Examples

vimma-ctl state                    # mode, workspace and tabs
vimma-ctl state --json             # the same, as JSON
vimma-ctl send-keys "ctrl+b ?"     # as if typed: opens the key list
vimma-ctl send-keys esc
vimma-ctl open https://example.com # in a new tab

In Hyprland, a key that shows Vimma's key list:

bind = SUPER, slash, exec, vimma-ctl send-keys "ctrl+b ?"

Keys go to the most recently focused Vimma window, exactly as if you typed them.

vimma-ctl and AI agents

The same program, run as vimma-ctl mcp, is the MCP server that local AI agents start. That side never has full control: it reaches only the agent workspace, and Vimma asks you before it carries out each request. While agents are on, each new full-control vimma-ctl connection is confirmed with you as well, since an agent with a shell could start one. :control on 15 turns full control on for 15 minutes, then off again.
