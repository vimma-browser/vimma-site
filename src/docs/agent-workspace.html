Local AI agents, such as Claude Code, Codex, opencode or GitHub Copilot, can use Vimma through vimma-ctl mcp, an MCP server. They reach one workspace only, agent, with its own cookies and logins, and every request asks you first.

off until you turn it on

Agents cannot reach Vimma until you type :mcp on and answer y. They never see your other workspaces, the private workspace or your logins there, and :mcp off disconnects them at once.

Connect an agent

  1. Build vimma-ctl and put it on your PATH (vimma-ctl, step 2).
  2. In Vimma, type :mcp on and press y.
  3. Add the server to your agent's tool. For Claude Code: claude mcp add --transport stdio --scope user vimma -- vimma-ctl mcp; for Codex: codex mcp add vimma -- vimma-ctl mcp. Other tools take the same command, vimma-ctl mcp, in their MCP settings.
  4. Ask the agent to open a page in Vimma's agent workspace. Its request appears at the foot of the window, and nothing happens until you answer.

Answer a request

Each request names the agent, the tool and what it touches: the tab's title and address, or the address it wants to open.

The question never interrupts your typing: while you type, or with focus in a text field, it waits, and the status bar says ◇ agent 1?. An unanswered request is denied after 50 seconds.

What an agent can do

  • List the agent workspace's tabs, read a tab's text (marked as untrusted web content), open an http or https address there, and close one of its tabs.
  • Download files, each after a question; they go to ~/Downloads/vimma-agent/ only, and Vimma never opens them.
  • Nothing else: pages there get no permission prompts and no pop-ups, and links to other apps open nothing.

To share a page of yours with an agent, move its tab to the agent workspace (m in the ctrl+b w picker). It is reopened with the agent workspace's cookies, never yours. :mcp revoke ends every grant, and :mcp forget clears the agent workspace's logins.
