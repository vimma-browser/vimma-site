Vimma's own agent, or a local AI agent such as Claude Code, Codex, opencode or GitHub Copilot through vimma-ctl mcp, can browse for you in one workspace only, agent, with its own cookies and logins. Vimma asks you before it carries out a request, and asks again before an agent pays or sends a form with text or personal details.

Your other workspaces stay out of reach

An agent never sees your other workspaces, the private workspace or your logins there. MCP agents cannot reach Vimma until you type :mcp on and answer y, and :mcp off disconnects them at once. Vimma's own agent needs no :mcp on, but it uses the same workspace, tools and questions.

Vimma's own agent

A chat window where you write a task, watch every step it takes, add instructions or stop it, all from the keyboard. It needs no separate program. It works only in the agent workspace and stops at the same checkpoints as any agent, whatever model drives it.

  1. Press ctrl+b i (or type :agent). The window opens where the side panel opens, with its input focused. A private window has no agent.
  2. Press Esc, then m, to pick a model: one on a local server (Ollama, LM Studio or the llama.cpp server, which Vimma finds on 127.0.0.1 while the picker is open), Anthropic's API or an OpenAI-compatible endpoint with your key, or an agent CLI you already use (Claude Code, Codex or Gemini CLI) on its own login, with no API key. A key goes into Firefox's login storage, encrypted, and is never shown again.
  3. Type the task and press Enter. That lets this conversation act in the agent workspace without asking at each step, for this one task. ctrl+Enter sends it and asks you before every step instead; shift+Enter starts a new line.
  • Where your data goes. The window's first line names the model and where the data goes, such as stays on this machine or page text sent to api.anthropic.com. Before the first task to a model off this machine, the window says what is sent (page text the agent reads, field values it sees, screenshots and your messages) and sends nothing until you press y. local_only = true under [agent] refuses every model that is not on this machine.
  • Checkpoints still ask. Sending a form, paying, showing you a page and the downloads that always ask still ask every time, in a bordered slot above the input that takes only y and n. Nothing you type in the input and nothing the model writes answers it.
  • Stop it with s after Esc, :agent stop or ctrl+b shift+a; the task's grant ends with it. q closes the window.
  • Give it a page with P (or :agent give): after a question, the tab moves to the agent workspace and is reopened with that workspace's cookies, never yours.
  • What is kept. Conversations survive a restart: your messages, the agent's replies and a short summary of each task, encrypted with your system keyring when you have one. Page text, element lists and screenshots are never stored. :agent forget all deletes every conversation.

Connect an agent's tool

  1. Use the vimma-ctl that came with Vimma, so it is updated with it. The .deb, the .rpm, the Arch Linux package and Homebrew put it on your PATH; with the tarball, the AppImage or the .dmg, put it there yourself or give your tool its full path (Install, under Details).
  2. In Vimma, type :mcp on and press y. Leave full control (vimma.control.enabled) off: agents do not need it.
  3. Add the server to your agent's tool. For Claude Code: claude mcp add --transport stdio --scope user vimma -- vimma-ctl mcp; for Codex: codex mcp add vimma -- vimma-ctl mcp; for Copilot: copilot mcp add vimma -- vimma-ctl mcp. Other tools, such as opencode, take the same command, vimma-ctl mcp, in their MCP settings.
  4. Ask the agent to open a page in Vimma's agent workspace. Its request appears at the foot of the window, and nothing happens until you answer.

Grants belong to the agent's session: when it quits, they end, and the next session asks again. To run Claude Code, Codex or Gemini CLI without a terminal and without :mcp on, pick it in Vimma's own agent instead.

Answer a request

Each request is one line at the foot of the window, above the status bar. It names the agent (as the agent calls itself), the tool and what it touches: the tab's title and address, or the address it wants to open.

ToPress
Allow it oncey
Allow this agent every tool until it quitsa
Allow this agent every tool for 15 minutes only15a
Deny itn, Esc or Enter
Deny it and ignore this agent until it reconnectsx
Answer a request that is waiting; with none, end every grantctrl+b shift+a
  • Nothing else answers. Any other key does nothing, and for its first second the line takes no key at all, so a key meant for something else cannot answer it.
  • It never interrupts your typing. While you type, or with focus in a text field, it waits, and the status bar says ◇ agent 1?. When Vimma is not in front, its window is marked urgent and a desktop notification names the agent and the kind of request, never an address or a title.
  • No answer is a no. A request nobody answers within 50 seconds (ask_timeout under [mcp]) is denied, and three noes in a row from one agent ignore it for a minute.
  • Grants show. The status bar says ◇ agent granted while an agent may act without asking, every request a grant lets through shows a notice, and :mcp log lists the last 100 requests. A grant is never written to disk.

What always asks

A grant lets an agent use every tool without asking: read, open, press keys, click, fill, take screenshots and download. These still ask every time, also under a grant, and your yes allows that one step without making or ending a grant:

  • Paying: a click, a fill or a followed link when the page shows a payment card field, or when the button says it pays (pay, buy, place order and the like, in several languages). The question shows the button, the site and the total the page states; the amount is the page's claim, and your statement is what counts.
  • Sending a form with text or personal details: a message, a name, an email or street address, a password, a payment card or one-time code, or a file. The question shows where the form goes and each field it sends; a password, card or one-time-code field shows as •••, never its value. A form that sends only the page's own values, such as a basket button with a quantity, runs under the grant. For a button that keeps asking, a (a always here) lets the same button on the same site send its form until the grant ends, unless it is a payment or sends a password, card, one-time-code or file field.
  • Showing you a page, since it changes what you see.
  • A dangerous or unscanned download, and a download a page started by itself.

A checkpoint starts with ▲ in your theme's warning colour. y runs that one step; n, Esc, Enter or x stops it. Password, payment card and one-time-code fields are never filled: the agent asks you to type them. A page that hides its checkout (no card field on screen, a button worded otherwise) is not recognised as a payment, so keep grants short on sites where you have a saved card, and read :mcp log after a task.

What an agent can do

An agent lists the agent workspace's tabs, reads a tab's text (marked as untrusted web content), opens an http or https address there and closes one of its tabs. On a page there it works much as you do with hints, in the background, so your window keeps its workspace, tab and focus:

ToThe agent uses
Scroll, find a word, follow a link, go back or forwardvimma_keys
List the buttons, fields and links on screen, each with a hint labelvimma_elements
Click one of themvimma_activate
Fill in fields, and send the form if you agreevimma_fill
See the page as you wouldvimma_screenshot
Read the page's script errors and failed requestsvimma_console
Show you one of its tabsvimma_show
  • Pages there get less than yours: no permission prompts, no pop-ups, and links to other apps open nothing.
  • Downloads ask and are kept apart, in ~/Downloads/vimma-agent/ only, readable by you alone. Vimma never opens them, refuses one over plain http, and scans each with ClamAV if your system has it.
  • To share a page of yours, move its tab to the agent workspace (m in the ctrl+b w picker). It is reopened with the agent workspace's cookies, never yours.

End an agent's access

  • ctrl+b shift+a with nothing waiting, or :mcp revoke: ends every grant now. The agents stay connected, and their next requests ask.
  • x on a question: denies everything that agent asked and ignores it until it reconnects.
  • :mcp off: disconnects every agent and ends their grants.
  • :mcp forget: deletes the agent workspace's cookies and site data, so any login an agent used there is gone.
  • Removing the server from your tool (claude mcp remove vimma, codex mcp remove vimma, copilot mcp remove vimma) stops it from starting.

An agent with a shell or file tools runs as you, and Vimma does not decide what it does with the rest of your computer: see What Vimma protects, and what it does not under Details, and keep your agent tool out of Vimma's profile folder.

Scripting with vimma-ctl

vimma-ctl also drives a running Vimma from a shell or a window-manager binding: it sends keys, reads the state and opens URLs, over a local control socket that is off until you turn it on.

Before you turn it on

The control socket gives full control of the browser to any program that has its token, which anything running as your user can read: such a program can type into your logged-in sites, change any setting and open local files. Leave it off unless you script Vimma. AI agents do not need it. While agents are on, each new full-control connection asks you first in Vimma, with a code that vimma-ctl prints in your terminal: answer y only if the codes match. :control on 15 turns full control on for 15 minutes, then off again.

  1. In about:config, set vimma.control.enabled to true. It starts at once.
  2. Use the vimma-ctl that came with Vimma. vimma-ctl --version names the Vimma version it came with.
vimma-ctl state                    # mode, workspace, tabs, and whether each is loading
vimma-ctl state --json             # the same, as JSON
vimma-ctl send-keys "ctrl+b ?"     # as if typed: opens the key list
vimma-ctl open https://example.com # in a new tab

Keys go to the most recently focused Vimma window, exactly as if you typed them. In Hyprland, bind = SUPER, slash, exec, vimma-ctl send-keys "ctrl+b ?" shows Vimma's key list.
