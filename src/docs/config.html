Everything you can change about Vimma's keys, behaviour and colours lives in one file: ~/.config/vimma/config.toml. Until you change something in it, you get the defaults.

Edit the file

  1. On a profile's first launch Vimma creates the file with every default written out and commented, so at first it changes nothing. The status bar reports created ~/.config/vimma/config.toml once. A file you already have is never touched, and :config shows it in a tab.
  2. Open it in your editor, uncomment or add what you want to change, and save.
  3. Vimma picks it up within two seconds, in every window. There is nothing to restart. :source reloads it at once.

Remap a key

The keys in these docs are defaults, not decisions: every binding, the ctrl+b prefix and the space leader can be remapped. Bindings go under [keys], by the action names in the Name column of the keys page. prefix+ means after the prefix, and <leader> after the leader, which has no default bindings: it is there for your own. A new binding replaces the default.

schema = 2

[keys]
prefix = "ctrl+a"                        # the prefix itself, as tmux users often remap it
new_tab = ["prefix+t"]                   # ctrl+a t opens a tab, instead of the default
toggle_sidebar = ["prefix+b", "<leader>n"] # the side panel: prefix b, and now also leader n

[modal]
leader = ","                             # the leader, space by default

Firefox's own keys, such as ctrl+t and F5, are bindings too and are remapped the same way (Firefox's keys are Vimma bindings).

Other things you can set

SectionWhat it changes
[panes]max: how many panes a split can have (1 to 16, default 8); layout: what ctrl+b enter does; main_size: the main pane's share in the main-* layouts; max_splits: how many splits a workspace keeps (1 to 9, default 9).
[sites."example.com"]insert: auto, never or always: whether text fields on that site put you in insert mode.
[theme]name: the built-in palette, "vimma" or "tokyo-night"; appearance: dark, light or the system's; source = "file" for the built-in palette instead of your Omarchy theme; [theme.colors] to change single colours (colours).
[workspaces]Workspaces that always exist (workspaces).
[[routes]]Send a site, or every link an app opens, to a workspace (routing).
[search]default: the default search engine; [search.aliases]: short @aliases such as @gh, for an installed engine or any search URL.
[bookmarks]root: what the bookmarks panel lists, the workspace's folder, the toolbar or everything (bookmarks).
[private]placement: on Hyprland and macOS, whether the private workspace takes your window's place or opens beside it (private workspace).
[mcp]Local AI agents: whether they may ask, their workspace's name, how long a question waits, how long a bare a lasts (agent workspace).
[ui]toolbar and bookmarks_toolbar: whether Firefox's toolbar and Bookmarks Toolbar show.
[updates]check = false: no update check at all.
[firefox]disable and enable: which of Firefox's own shortcuts are off (Firefox's shortcuts).
[modal]insert_editing = false turns off ctrl+w, ctrl+u and ctrl+h in text fields.

Keep schema = 2 as the first line: it enables [panes], [sites], [[routes]], [firefox], [bookmarks], [private], [mcp], [search], [ui], [updates], insert_editing, hint characters and the theme's name and appearance.

If you make a mistake

A file with an error is not applied at all, so your last working setup keeps working. The status bar shows the first error in red, with its line number, for example config.toml:3: keys.new_tabb: unknown action "new_tabb" (did you mean "new_tab"?). Fix the line and save; the message goes away. about:vimma lists every error.

about:config and about:vimma

A few switches live in about:config instead, such as vimma.ui.tabstrip.hidden to bring Firefox's tab strip back; they are listed under Details. about:vimma (or :about) shows what Vimma is doing: its version, your config and its errors, the theme, the workspaces, and the last keys it saw.

Colours and Omarchy

Vimma's and Firefox's own parts of the window share one colour theme: Vimma's status bar, command line, pickers, link hints, pane borders and start page, and Firefox's toolbar, address bar, menus, dialogs and Settings pages. Out of the box it is Vimma's own palette, the aqua, magenta and teal-black of this site, in a dark and a light variant.

SourceWhat you get
Omarchy, if you use itYour current Omarchy theme, followed live. This is the default whenever Omarchy is installed.
Built inVimma's palette, dark or light to match your system, or Tokyo Night. The default when Omarchy is not installed.
Your config.tomlSingle colours of your choice, on top of either one.

Dark or light

The built-in palette follows your system's dark or light setting and switches the moment it changes. :theme dark or :theme light keeps it one way, :theme system follows the system again, and a bare :theme switches to the other one. Vimma remembers the choice across restarts. appearance under [theme] sets the same in the file, and then the file wins over :theme.

Your own colours

Pick the built-in palette and change single colours under [theme]. Save, and every window recolours within two seconds:

schema = 2

[theme]
name = "tokyo-night"  # the built-in palette: "vimma" (the default) or "tokyo-night"
source = "file"       # on Omarchy: the built-in palette instead of your Omarchy theme
[theme.colors]
accent = "#ff9e64"

To use the built-in palette on Omarchy without a config file, set vimma.theme.source to builtin in about:config.

With Omarchy

There is nothing to set up. Switch themes with omarchy-theme-set or the Omarchy menu, and every Vimma window follows, without a restart.

So that it changes at the same moment as the rest of your desktop, Vimma installs a small hook, vimma-theme-reload.sh, in ~/.config/omarchy/hooks/theme-set.d/ the first time it starts. If you edit the hook, Vimma leaves it alone; if you delete it, Vimma does not recreate it. Without the hook, Vimma still notices a new theme within two seconds. Without Omarchy, Vimma looks for it once at startup and then reads nothing more.
