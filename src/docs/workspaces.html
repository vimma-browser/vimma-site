A workspace is a set of tabs with its own cookies and logins, like a separate browser profile one key away. Keep work in one and personal browsing in another: signing in to a site in one does not sign you in to it in the other.

Under the hood each workspace is a Firefox container. ctrl+b ( and ctrl+b ) step through them, as tmux's session keys do. A window shows one workspace at a time; the others' tabs are hidden, not closed, and everything comes back after a restart.

Make your first workspace

  1. Press ctrl+b shift+n. The command line opens with :wsnew typed for you.
  2. Type a name, such as work, and press Enter. You are now in it: the status bar shows ● 2:work.
  3. Sign in to something. Press ctrl+b ( to go back to main: you are not signed in there.
  4. ctrl+b ) takes you forward to work again.

Good to know

  • Closing a workspace you made deletes its cookies, logins and site data. Vimma asks first; press y to close it, anything else to keep it.
  • Moving a tab reopens it in the other workspace: it keeps its address, but loses its back/forward history and anything typed into forms.
  • New tabs open in the workspace you are in. A link you click opens in the page's own workspace, even in a new tab.
  • Tab numbers, ctrl+b n / ctrl+b p and closing tabs stay within the workspace; ctrl+b g lists every workspace's tabs.
  • If you think of a workspace as a Vim buffer, the commands follow: :wa adds one and :wd closes one, as :badd and :bd do.
  • Site permissions (camera, microphone, location, notifications) are per workspace too, like logins.
  • Each workspace has its own bookmarks folder.
  • Two workspaces are special: the private workspace (ctrl+b shift+p), Firefox's private browsing, and the agent workspace, the only one local AI agents can reach. ctrl+b ( and ) skip both; the picker lists them last.
  • You can declare workspaces in config.toml, and send sites or apps to one automatically: see below.

The private workspace

The private workspace is Firefox's private browsing, reached like any other workspace. Because it is a real Firefox private window, the history, cookies, site storage, cache, form history and download records it collects are discarded when you close it.

  1. Press ctrl+b shift+p (or ctrl+shift+p, or :private). The private workspace opens, and the status bar says ◆ private.
  2. Browse as usual: hints, find, splits, copy mode and the side panel work as in any workspace.
  3. Press ctrl+b shift+p again, or ctrl+^, to go back to where you were. The private workspace stays open, one key away.
  4. When you are done, ctrl+b shift+d in it (or :private close anywhere) asks for confirmation (y/N), then closes it and discards its data.

Good to know

  • Reached by its own key only. ctrl+b ( / ), ]w / [w and ctrl+^ never land in it by accident; from inside it, they take you out.
  • There is only one. Every private window belongs to it, and they all share one cookie jar, as Firefox's private windows do.
  • The workspace picker (ctrl+b w) lists it last, with a tab count only, never a title or an address. m on that row reopens the current tab there; a private tab never moves out.
  • On Hyprland it takes your Vimma window's place, in the same tile and size, and your normal window comes back when you switch or close the private window. On macOS it does the same, at your window's frame, unless the window is in full screen. Elsewhere it is a second window.
  • Add-ons run there only if you allowed them in private windows (ctrl+b e, then P).
  • Not hidden: the clipboard. What you copy there stays there after the workspace closes. The window's title, on the other hand, is always Vimma Private Browsing, never the page's.

Send sites to a workspace

Routing puts each link in the workspace it belongs to, without you having to think about it. Send github.com to your work workspace, or every link Slack opens, and the page arrives there with that workspace's logins, wherever you clicked it.

Write your first rule

  1. Go to a site that belongs in a workspace, such as github.com.
  2. Type :route add work and press Enter. Vimma appends a rule for the site to config.toml.
  3. From now on, an address you type, a bookmark or a link from another app on that site opens in work.

Or write the rules yourself in config.toml. The first rule that matches, top to bottom, wins:

schema = 2

[[routes]]
domain = "github.com"   # the site and its subdomains
workspace = "work"

[[routes]]
app = "slack"           # every link Slack opens
workspace = "work"

Commands

ToType
See every rule, and which one matches this tab:route
Send this site to this workspace, or to work:route add, :route add work
Move this tab to the workspace its rule names:route move

Good to know

  • Rules apply to what you open yourself: an address you type, :open, a bookmark or a link from another app. A link that a page opens stays in that page's workspace, so no site can open another site with your other logins. The status bar names the workspace the rule would choose, and :route move takes the tab there.
  • Routing by app works through vimma-open, which Vimma's packages register as the system's browser command. A link from an app Vimma cannot identify, a Flatpak for example, follows only the domain and url rules.
  • Private windows are never routed.
