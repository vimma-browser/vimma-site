Vimma {{version}} · Linux x86_64 · macOS

Install

Vimma {{version}}, on Firefox {{firefox}}, is released for Linux x86_64 and for macOS 15 (Sequoia) or later on Apple Silicon (M1 or later). There is no build for Intel Macs or Windows.

Arch Linux

One command adds Vimma's signed pacman repository and installs Vimma, and from then on updates come with your system upgrade, sudo pacman -Syu. It imports the key that signs the repository, trusts it, adds the repository to the end of /etc/pacman.conf unless it is already there, and installs the package; it stops at the first step that fails, and running it again is harmless:

$ curl -fsSL https://updates.vimma.dev/vimma-packages.asc | sudo pacman-key --add - \
    && sudo pacman-key --lsign-key 110649CB2BC11400828DD0D497FD3D2B24AD4390 \
    && { grep -q '^\[vimma\]' /etc/pacman.conf || printf '\n[vimma]\nSigLevel = Required\nServer = https://updates.vimma.dev/arch/$arch\n' | sudo tee -a /etc/pacman.conf >/dev/null; } \
    && sudo pacman -Syu vimma-bin

The key's fingerprint is 1106 49CB 2BC1 1400 828D D0D4 97FD 3D2B 24AD 4390; the second step trusts only the key with that fingerprint, and fails if the key you imported has another. SigLevel = Required makes pacman refuse the repository's package list, not only its packages, unless it is signed.

Step by step

Import the key and trust it:

$ curl -fsSL https://updates.vimma.dev/vimma-packages.asc | sudo pacman-key --add -
$ sudo pacman-key --lsign-key 110649CB2BC11400828DD0D497FD3D2B24AD4390

add the repository to the end of /etc/pacman.conf:

[vimma]
SigLevel = Required
Server = https://updates.vimma.dev/arch/$arch

and install Vimma:

$ sudo pacman -Syu vimma-bin

The vimma-bin package is built and signed with each release, so nothing is built on your machine. It installs Vimma to /opt/vimma with vimma on your PATH, a desktop entry and icons. pacman checks the signatures of the repository and of the package. sudo pacman -R vimma-bin removes Vimma; your profile stays in your home directory.

Or build the same package yourself from the release's PKGBUILD, as your normal user, from any directory:

$ {{arch_install}}

It builds in ~/.cache/vimma-build, about 450 MB while it builds, which you can delete at any time. makepkg -si asks for your password to install the package and refuses to run as root. Without the repository, a system upgrade does not update Vimma: run the same command again for each release. A package built this way moves to the repository on the next sudo pacman -Syu after you add it, since both are vimma-bin.

Debian and Ubuntu

On Debian 12 or later and Ubuntu 22.04 or later, one command adds Vimma's signed apt repository and installs Vimma, and from then on updates come with your system upgrade, sudo apt upgrade. The repository's setup is one file, which holds the key and trusts it for this repository only, never for the rest of the system:

$ curl -fsSL https://updates.vimma.dev/apt/vimma.sources | sudo tee /etc/apt/sources.list.d/vimma.sources >/dev/null \
    && sudo apt update && sudo apt install vimma

The key in it has the fingerprint 1106 49CB 2BC1 1400 828D D0D4 97FD 3D2B 24AD 4390. apt checks the repository's signature and each package's checksum against it. sudo apt remove vimma removes Vimma; your profile stays in your home directory.

Step by step

Add the repository's file:

$ curl -fsSL https://updates.vimma.dev/apt/vimma.sources | sudo tee /etc/apt/sources.list.d/vimma.sources

then install Vimma:

$ sudo apt update && sudo apt install vimma

Fedora

One command adds Vimma's signed rpm repository and installs Vimma, and from then on updates come with your system upgrade, sudo dnf upgrade:

$ sudo dnf config-manager addrepo --overwrite --from-repofile=https://updates.vimma.dev/rpm/vimma.repo \
    && sudo dnf install vimma

dnf shows the key's fingerprint and asks once before it trusts it: accept it only if it is 1106 49CB 2BC1 1400 828D D0D4 97FD 3D2B 24AD 4390. It then checks the signatures of the repository and of each package. --overwrite lets the command run again over the repository it added before. sudo dnf remove vimma removes Vimma; your profile stays in your home directory.

Step by step 
$ sudo dnf config-manager addrepo --from-repofile=https://updates.vimma.dev/rpm/vimma.repo
$ sudo dnf install vimma

openSUSE

One command adds Vimma's signed rpm repository, unless it is already there, and installs Vimma, and from then on updates come with your system upgrade, sudo zypper up:

$ { zypper lr vimma >/dev/null 2>&1 || sudo zypper addrepo --refresh --gpgcheck-strict https://updates.vimma.dev/rpm/vimma.repo; } \
    && sudo zypper refresh && sudo zypper install vimma

zypper shows the key's fingerprint and asks once before it trusts it: accept it only if it is 1106 49CB 2BC1 1400 828D D0D4 97FD 3D2B 24AD 4390. It then checks the signatures of the repository and of each package. sudo zypper remove vimma removes Vimma; your profile stays in your home directory.

Step by step 
$ sudo zypper addrepo --refresh --gpgcheck-strict https://updates.vimma.dev/rpm/vimma.repo
$ sudo zypper refresh && sudo zypper install vimma

macOS

{{dmg_note}}

For Macs with Apple Silicon, on macOS 15 (Sequoia) or later; Homebrew refuses the cask on an older macOS. With Homebrew, install the cask from Vimma's own tap:

$ brew install --cask vimma-browser/tap/vimma

Homebrew checks the download against the checksum the cask pins, puts Vimma in Applications and vimma on your PATH. brew upgrade --cask vimma updates it, brew uninstall --cask vimma removes it and keeps your profile, and brew uninstall --zap --cask vimma removes your profiles, caches and preferences as well; your ~/.config/vimma/ stays.

Without Homebrew, download {{dmg}} from the Vimma {{dmg_version}} release, open it and drag Vimma into Applications. Its checksum is in SHA256SUMS-macos, signed like the Linux files.

Vimma is signed with its Apple Developer ID and notarised by Apple, so it opens like any other app: the first time, macOS only asks whether to open an app downloaded from the internet.

On a Mac, passkeys stored in macOS (iCloud Keychain) do not work yet, and your profile lives in ~/Library/Application Support/Vimma/.

Other distributions and direct downloads

The latest release, {{version}}, has these files for Linux x86_64, each with one command that downloads it and installs or starts it.

The AppImage, {{appimage}}, saved to ~/Apps and started; it updates itself:

$ mkdir -p ~/Apps && curl -fL -o ~/Apps/{{appimage}} https://github.com/vimma-browser/vimma/releases/download/{{release_tag}}/{{appimage}} \
    && chmod +x ~/Apps/{{appimage}} && ~/Apps/{{appimage}}

The tarball, {{tarball}}, unpacked into ~/Apps/vimma and started; it updates itself:

$ mkdir -p ~/Apps && curl -fL https://github.com/vimma-browser/vimma/releases/download/{{release_tag}}/{{tarball}} | tar -xJ -C ~/Apps \
    && ~/Apps/vimma/vimma

The .deb, for Debian 12+ and Ubuntu 22.04+:

$ curl -fL -o /tmp/{{deb}} https://github.com/vimma-browser/vimma/releases/download/{{release_tag}}/{{deb}} \
    && sudo apt install /tmp/{{deb}}

The .rpm, on Fedora:

$ curl -fL -o /tmp/{{rpm}} https://github.com/vimma-browser/vimma/releases/download/{{release_tag}}/{{rpm}} \
    && sudo dnf install /tmp/{{rpm}}

and on openSUSE, where the command first imports the key that signs Vimma's packages, the one with the fingerprint 1106 49CB 2BC1 1400 828D D0D4 97FD 3D2B 24AD 4390, because zypper refuses a package file whose key it has not imported; zypper then checks the file's signature:

$ curl -fL -o /tmp/{{rpm}} https://github.com/vimma-browser/vimma/releases/download/{{release_tag}}/{{rpm}} \
    && sudo rpm --import https://updates.vimma.dev/vimma-packages.asc \
    && sudo zypper install /tmp/{{rpm}}

Step by step, download the file from the release page instead and run the last part of its command. A .deb or .rpm installed from a file is not updated by a system upgrade: install the next release's file over it, or add the repository above. Next to the files are SHA256SUMS, an SBOM and cosign signatures. Installing, in the guide, explains how to check them.

Updates

Since 0.1.2, Vimma checks for a new release every 12 hours, or at once with :update. When one is out, the status bar shows ⇡ and its version (in red for a security release), and :update shows the command for how you installed Vimma; each update file is checked with SHA-512. From a package repository, updates come with your system upgrade: sudo pacman -Syu, sudo apt update && sudo apt upgrade, sudo dnf upgrade or sudo zypper up. The AppImage and the tarball update themselves: the AppImage replaces its own file with the new release, the tarball installs it through Firefox's updater, and either runs the new version from the next start. A .deb or .rpm installed from a file, or a package built with makepkg, only tells you: install the newer release the same way, or add the repository for your distribution above. A 0.1.1 install has no update check, so update it by hand once.

On a Mac, the notice and :update work the same way: run brew upgrade --cask vimma, or install the newer .dmg over the old one.

Build from source

To build Vimma yourself, clone https://github.com/vimma-browser/vimma and follow the steps below. A source build has Safe Browsing off unless you add your own Google key: see below.

Requirements

  • Linux x86_64, for the macOS build too: it is cross-compiled on Linux (CONTRIBUTING.md has the steps).
  • About 35 GB of free disk: the Firefox source and full build take 27 GB, the compiler cache 6.8 GB, Mozilla's toolchains 3.1 GB and the source download 0.8 GB.
  • Node.js 22.18 or later in the 22 line, or 24.3 or later (^22.18.0 || >=24.3.0); Python 3.10 to 3.14; git; and gpgv, which checks the Firefox source against Mozilla's signature.
  • Time: about 40 minutes for the first full build on a 16-thread machine, plus the Firefox source download.

Build

$ git clone https://github.com/vimma-browser/vimma.git && cd vimma
$ npm ci                  # dev tools, including Surfer
$ npx surfer download     # Firefox source into engine/
$ npm run verify-source   # check it against Mozilla's signed checksums
$ npx surfer bootstrap    # Mozilla's toolchains into ~/.mozbuild (once)
$ npm run import          # apply Vimma's files and patches
$ npm run build           # full build

Google Safe Browsing

Google Safe Browsing (phishing and malware protection) needs an API key, which is not in the repository. A build without one works, but Safe Browsing is off. To turn it on, get a free key from Google and save it as ~/.config/vimma/keys/safebrowsing before building (the runbook has the steps).

Run

$ npm start               # your build, with its own profile
$ npm start -- --fresh    # a throwaway profile instead

npm start runs Vimma with a profile of its own (~/.cache/vimma-dev-profile), so your Firefox profile is never touched. Press ctrl+b ? to see every binding.

To update a source build, pull the latest main, then run npm run import and npm run build again. When the pull moves Vimma to a new Firefox release, npm run import refuses the old source: run npx surfer download --force and npm run verify-source first. --force deletes engine/ with its build, so the next npm run build is a full one.
